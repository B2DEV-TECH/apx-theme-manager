# Native APEX application

`manager/` is the authorable APEXlang source for the original APEX Theme Manager
application. It uses Universal Theme regions, Cards, Classic Reports, page items,
buttons, authorization schemes and page processes. The login, base theme and icon
files originate from this project's own App Builder skeleton.

`f104.sql` is the complete SQL export generated by the public
`APEX_EXPORT.GET_APPLICATION` API. Its default application ID is a source artifact
identifier. The installer overrides workspace, parsing schema and application ID
through `APEX_APPLICATION_INSTALL`; it refuses an existing destination ID.

Install the database service first, then follow
[`../docs/installation/README.md`](../docs/installation/README.md) and the scripts
in [`../installer/`](../installer/). Importing the app does not register targets,
enable the engine modification policy or grant an actor access.

The application's **Modify Other Applications** runtime API setting is explicit
because reviewed definition recovery is its purpose. This is workspace-wide APEX
authority. Use a dedicated trusted administration application and the engine's
separate registry, named principals and development policy.

The runtime workflow uses these pages:

| Page | Purpose |
| --- | --- |
| 1 | Overview, native Cards and registered applications |
| 10 | Application details, immutable snapshots, comparison and restore preview |
| 20 | Classified differences, filters and explicit eligible selections |
| 30 | Exact preview, fingerprints, protected token and typed POST confirmation |
| 40 | Operation results, backup downloads and append-only audit history |
| 50 | Workflow guide, supported scope and recovery limitations |
| 60 | Authorized snapshot ZIP download |
| 61 | Authorized proposed-definition ZIP download |
| 9999 | Native APEX Accounts authentication |

Every report restricts its rows through engine authorization. The engine repeats
authorization at mutation and download boundaries. Report values are escaped;
the few HTML columns contain fixed link text and generated URLs for numeric IDs.
The one-use preview token is held in encrypted, restricted APEX session state.
Full definition restore requires identical ACL assignment state in the snapshot
and current application. A mismatch is rejected for explicit manual review;
the tool does not reset ACL assignments or restore database table data.

Local authoring was validated with SQLcl 26.3 against APEX 26.2.0. The scripts
`scripts/apex-lab.mjs` and `scripts/apex-browser-smoke.mjs` are optional development
tools; Node is not a runtime dependency. The ignored `.local/lab.json` provides
local connection and test-account settings. Do not commit that file.

`scripts/apex-browser-workflow.mjs --disposable-lab` is a separate destructive
integration scenario, guarded to this project's original local sample ID and
application names. It captures a baseline, changes the sample through supported
imports, and exercises reviewed recovery, restore and download workflows. An
optional `--record` saves real Playwright video with per-test timing evidence
under `.local/ui-agent-workflow/`. These recordings are automated browser runs
using synthetic layouts. Run this scenario only while the local fixture is free
from other tests or manual edits.
